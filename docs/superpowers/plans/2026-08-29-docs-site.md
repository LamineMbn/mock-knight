# Mock Knight documentation site — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a seven-page static site at `https://laminembn.github.io/mock-knight/` where each page owns one search-query cluster, so Mock Knight is findable by the people who need it.

**Architecture:** A new `packages/site` Astro package that imports nothing from the workspace. It renders from three sources of truth it does not own — the generated `tokens.css` for colour, the committed `schema/mock-knight.schema.json` for the configuration reference, and `docs/faq.md` for the FAQ — so the site cannot state a fact the program contradicts. Static output, zero JavaScript except one deliberate hero interaction, deployed by GitHub Actions.

**Tech Stack:** Astro 5, Tailwind 4 (`@tailwindcss/vite`, already in the repo), `@astrojs/sitemap`, Playwright (a second config, separate from tier 4), Vitest (the existing root tier), Lighthouse CI.

**Spec:** `docs/superpowers/specs/2026-08-29-docs-site-design.md` — read it before Task 1. This plan argues from it and does not restate its reasoning.

## Global Constraints

Every task's requirements implicitly include all of these.

- **Node ≥ 22.** The repo floor; `better-sqlite3` v13 sets it.
- **`site: 'https://laminembn.github.io'`, `base: '/mock-knight'`, `trailingSlash: 'always'`.** Confirmed live: `gh api repos/LamineMbn/mock-knight/pages` returns `build_type: workflow` and `html_url: https://laminembn.github.io/mock-knight/`.
- **Every internal URL goes through the `href()` helper (Task 1).** A hardcoded `/wiremock/` works in `astro dev` and 404s in production. Task 9 fails the build on any that slip through.
- **Invariant 1 — layering.** `packages/site` imports nothing from `@mock-knight/*`. Enforced by lint in Task 1.
- **Invariant 8 — colour comes from tokens.** No literal colour anywhere in the package. A value that does not exist goes into `design/design-tokens.py`, then `pnpm tokens:css`. The site defines no `--mk-*` token of its own.
- **Invariant 4 applied to copy.** A capability that is off is *stated with its reason*, never omitted. Task 4 tests this.
- **Two font families, self-hosted.** Inter and JetBrains Mono via the existing `@fontsource-variable` packages. No Google Fonts link, no third font.
- **Semantic green and red appear only where they mean matched and unmatched.** Nowhere decorative.
- **Never colour alone.** Every pass/fail state carries hue **and** a glyph **and** a text label.
- **Responsive to 360px**, visible keyboard focus, `prefers-reduced-motion` respected.
- **Titles ≤ 60 characters and unique; descriptions ≤ 160.** Asserted by unit test in Task 2.
- **Voice (design brief §9):** plain, specific, calm. The product's real nouns — stub, mapping, scenario, journal, profile. No themed vocabulary, no exclamation marks, no "Uh oh".
- **TypeScript `strict`, no `any`** — `unknown` plus a parse instead.
- **Commits:** imperative, scoped `site:` (or `docs:` / `ci:` where the change is not in the package). No co-author trailer.

- [ ] **Step 3: Implement `href.ts`**

```ts
/**
 * Every internal URL carries the base path GitHub Pages serves this site under.
 *
 * A hardcoded `/wiremock/` resolves correctly in `astro dev`, which serves from the base, and
 * 404s in production. That is the standard failure of a Pages project site and it is invisible
 * until deploy, so links go through here and `scripts/check-links.mjs` fails the build on any
 * that do not.
 *
 * `joinBase` is separate from `href` so it can be tested without a Vite environment supplying
 * `import.meta.env`.
 */
export function joinBase(base: string, path: string): string {
  const trimmedBase = base.replace(/\/+$/, '')
  const trimmedPath = path.replace(/^\/+/, '').replace(/\/+$/, '')
  if (trimmedPath === '') return trimmedBase === '' ? '/' : `${trimmedBase}/`
  return `${trimmedBase}/${trimmedPath}/`
}

export function href(path: string): string {
  return joinBase(import.meta.env.BASE_URL, path)
}
```

- [ ] **Step 5: Write the asset preparation script**

`packages/site/scripts/prepare-assets.mjs`. Two things live outside this package and have to be brought in, because Astro serves only its own `public/` and CSS cannot reach across a package boundary without pretending the boundary is not there.

```js
#!/usr/bin/env node
/**
 * Copy the two things this package renders from but does not own.
 *
 * `tokens.css` is generated into the *web* package by `pnpm tokens:css`, and `docs/images/`
 * sits at the repository root where the README needs it. Both are copied rather than
 * symlinked: a symlink survives a local build and does not survive `upload-pages-artifact`,
 * which is a failure that only appears in production.
 *
 * Both copies are gitignored. The originals stay the single committed home.
 */
import { copyFile, mkdir, readdir, rm } from 'node:fs/promises'
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'

const here = dirname(fileURLToPath(import.meta.url))
const root = join(here, '..', '..', '..')

const TOKENS_SOURCE = join(root, 'packages', 'web', 'src', 'styles', 'tokens.css')
const TOKENS_TARGET = join(here, '..', 'src', 'styles', 'tokens.generated.css')
const IMAGES_SOURCE = join(root, 'docs', 'images')
const IMAGES_TARGET = join(here, '..', 'public', 'images')

await mkdir(dirname(TOKENS_TARGET), { recursive: true })
await copyFile(TOKENS_SOURCE, TOKENS_TARGET)

// Removed first, so a screenshot deleted upstream does not linger in the published site.
await rm(IMAGES_TARGET, { recursive: true, force: true })
await mkdir(IMAGES_TARGET, { recursive: true })
const images = (await readdir(IMAGES_SOURCE)).filter((name) => name.endsWith('.png'))
for (const name of images) {
  await copyFile(join(IMAGES_SOURCE, name), join(IMAGES_TARGET, name))
}

console.log(`prepare-assets: tokens.css and ${images.length} screenshots copied in`)
```

- [ ] **Step 3: Implement `routes.ts`**

Paths here are base-relative. `href()` adds `/mock-knight`.

```ts
/**
 * Every page, once.
 *
 * The nav, each page's `<head>`, the sitemap and the tests all read this list, so adding a page
 * is one edit and forgetting to link it is impossible. Titles and descriptions live here rather
 * than in each page because their constraints — unique, ≤60, ≤160 — are properties of the *set*,
 * and a rule about a set cannot be checked from inside one member of it.
 */
export interface Route {
  /** Base-relative, leading and trailing slash. */
  readonly path: string
  /** The `<title>`. ≤60 characters or Google truncates it mid-word. */
  readonly title: string
  /** The meta description. Not a ranking factor; it is the snippet people decide from. */
  readonly description: string
  /** Label in the top nav, or null for pages reachable from the body only. */
  readonly nav: string | null
}

export const ROUTES: readonly Route[] = [
  {
    path: '/',
    title: 'Mock Knight — a web UI for WireMock',
    description:
      'Open-source web UI for WireMock, MockServer, Mockoon and Prism. Search thousands of stubs, see why a request did not match, and edit safely. Runs with npx.',
    nav: null,
  },
  {
    path: '/wiremock/',
    title: 'WireMock UI — browse and edit stubs in a browser',
    description:
      'WireMock ships an admin API and no UI. Mock Knight is one: full-text and structured search over your stubs, a live request journal, and safe edits on a shared server.',
    nav: 'WireMock',
  },
  {
    path: '/mockserver/',
    title: 'MockServer UI — search and edit expectations',
    description:
      'A browser UI for MockServer: search every expectation, read and edit them as forms or raw JSON, and see which one answers a path. No traffic log — MockServer records none.',
    nav: 'MockServer',
  },
  {
    path: '/mockoon/',
    title: 'Mockoon environments in a shared web UI',
    description:
      'Read and edit a Mockoon environment file from a browser, with a traffic log — for the shared and CI setups where Mockoon’s own desktop app is not what is running.',
    nav: 'Mockoon',
  },
  {
    path: '/prism/',
    title: 'Prism UI — read the stubs an OpenAPI mock serves',
    description:
      'See what Stoplight Prism will actually return: every operation as one stub per declared response, ranked the way Prism picks. Read-only, because Prism has no control API.',
    nav: 'Prism',
  },
  {
    path: '/config/',
    title: 'Configuring Mock Knight — mock-knight.json',
    description:
      'Every field of mock-knight.json, generated from the JSON Schema the program validates against: profiles, allowedHosts, authentication and environment interpolation.',
    nav: 'Config',
  },
  {
    path: '/faq/',
    title: 'Mock Knight FAQ',
    description:
      'Does WireMock have a UI? How is this different from WireMock Cloud? Will it rewrite my mapping files? Is it safe to point at a mock server my team shares?',
    nav: 'FAQ',
  },
]

export function routeFor(path: string): Route {
  const found = ROUTES.find((route) => route.path === path)
  if (found === undefined) throw new Error(`No route declared for "${path}". Add it to ROUTES.`)
  return found
}
```

```astro
---
/**
 * The product's whole loop, in five seconds, with nothing installed.
 *
 * Rendered server-side in the state that explains the product — unmatched — so it is meaningful
 * before, and without, the script. The script is progressive enhancement and roughly forty lines
 * of it; nothing else on this site ships any.
 *
 * The shape is the real explainer's: candidates ranked, then a field-by-field comparison with
 * the passes quiet and the failures loud (design brief §2.3).
 */
const TENANTS = ['acme', 'globex', 'umbrella', 'initech'] as const
/** Tenants a stub exists for. `initech` is not one, which is the point. */
const STUBBED = ['acme', 'globex', 'umbrella'] as const
const INITIAL = 'initech'

const closest = STUBBED[0]
const rows = [
  { field: 'method', expected: 'POST', actual: 'POST', id: 'method' },
  { field: 'url', expected: '/payments/v2/charges', actual: '/payments/v2/charges', id: 'url' },
  { field: 'headers.X-Tenant', expected: closest, actual: INITIAL, id: 'header' },
]
---

<section aria-labelledby="hero-heading" role="region" aria-label="Why a request did not match">
  <div class="thesis">
    <h1 id="hero-heading">A web UI for WireMock</h1>
    <p>Your mock server returned 404 and will not say why. This says why.</p>
    <code>npx mock-knight --url http://localhost:8080</code>
  </div>

  <div class="explainer" data-stubbed={STUBBED.join(',')} data-closest={closest}>
    <p class="request">
      <span class="method">POST</span> <span class="path">/payments/v2/charges</span>
    </p>
    <p>
      <label for="tenant">X-Tenant</label>
      <select id="tenant" name="tenant">
        {TENANTS.map((tenant) => <option value={tenant} selected={tenant === INITIAL}>{tenant}</option>)}
      </select>
    </p>

    <table>
      <thead>
        <tr><th scope="col">Field</th><th scope="col">Expected</th><th scope="col">Actual</th><th scope="col">Result</th></tr>
      </thead>
      <tbody>
        {
          rows.map((row) => (
            <tr data-testid={`row-${row.id}`} data-state={row.expected === row.actual ? 'pass' : 'fail'}>
              <td>{row.field}</td>
              <td>{row.expected}</td>
              <td data-cell={row.id === 'header' ? 'actual-tenant' : undefined}>{row.actual}</td>
              <td>
                <span aria-hidden="true">{row.expected === row.actual ? '✓' : '✗'}</span>
                <span>{row.expected === row.actual ? 'matched' : 'failed'}</span>
              </td>
            </tr>
          ))
        }
      </tbody>
    </table>

    <p data-testid="verdict" aria-live="polite" data-state="fail">✗ 1 of 3 predicates failed</p>
  </div>
</section>

<script>
  /**
   * Forty lines, no framework, no hydration. It reads the same data attributes the server
   * rendered from, so the two can never disagree about which tenants have stubs.
   */
  const explainer = document.querySelector<HTMLElement>('.explainer')
  const select = document.querySelector<HTMLSelectElement>('#tenant')
  const headerRow = document.querySelector<HTMLElement>('[data-testid="row-header"]')
  const verdict = document.querySelector<HTMLElement>('[data-testid="verdict"]')

  if (explainer && select && headerRow && verdict) {
    const stubbed = (explainer.dataset.stubbed ?? '').split(',')
    const closest = explainer.dataset.closest ?? ''
    const expectedCell = headerRow.children[1] as HTMLElement
    const actualCell = headerRow.querySelector<HTMLElement>('[data-cell="actual-tenant"]')
    const resultCell = headerRow.children[3] as HTMLElement

    select.addEventListener('change', () => {
      const tenant = select.value
      const matched = stubbed.includes(tenant)
      // When it matches, the stub being explained *is* that tenant's. When nothing matches, the
      // explainer falls back to the closest — which is what the application does.
      const expected = matched ? tenant : closest

      expectedCell.textContent = expected
      if (actualCell) actualCell.textContent = tenant
      headerRow.dataset.state = matched ? 'pass' : 'fail'
      resultCell.innerHTML = matched
        ? '<span aria-hidden="true">✓</span><span>matched</span>'
        : '<span aria-hidden="true">✗</span><span>failed</span>'

      verdict.dataset.state = matched ? 'pass' : 'fail'
      verdict.textContent = matched ? '✓ matched — 3 of 3 predicates' : '✗ 1 of 3 predicates failed'
    })
  }
</script>
```

Style it in `site.css` with `[data-state='fail']` and `[data-state='pass']` selectors reading `--mk-status-unmatched-*` and `--mk-status-matched-*`. Check the exact token names in `packages/web/src/styles/tokens.css` before writing them — do not guess, and do not add a token.

```js
#!/usr/bin/env node
/**
 * One FAQ, two renderings.
 *
 * `docs/faq.md` is the source. This writes it into README.md between two markers; the site
 * imports the same file. CI runs this and then `git diff --exit-code`, so a stale README fails
 * the build — the same guarantee `tokens.css` and `schema/mock-knight.schema.json` have.
 *
 * Heading levels differ between the two surfaces and that is the detail a naive injector gets
 * wrong. The source writes each question as `##`. In the README they sit beneath `## FAQ`, so
 * they are demoted to `###`. On the site they render unchanged beneath the page's own `<h1>`.
 * Both are correct outlines; neither is the source's literal level.
 *
 * Usage: node scripts/faq.mjs [--check]
 */
import { readFileSync, writeFileSync } from 'node:fs'
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'

const root = join(dirname(fileURLToPath(import.meta.url)), '..')
const START = '<!-- faq:start -->'
const END = '<!-- faq:end -->'

const source = readFileSync(join(root, 'docs', 'faq.md'), 'utf8').trim()
const readmePath = join(root, 'README.md')
const readme = readFileSync(readmePath, 'utf8')

const start = readme.indexOf(START)
const end = readme.indexOf(END)
if (start === -1 || end === -1) {
  console.error(`README.md has no ${START} / ${END} pair. Add them under the FAQ heading.`)
  process.exit(2)
}

// Only headings at the start of a line, so a `##` inside a fenced block is left alone.
const demoted = source.replace(/^## /gm, '### ')
const next = `${readme.slice(0, start + START.length)}\n\n${demoted}\n\n${readme.slice(end)}`

if (process.argv.includes('--check')) {
  if (next !== readme) {
    console.error('README.md’s FAQ is stale. Run `pnpm faq` and commit the result.')
    process.exit(1)
  }
  console.log('README.md’s FAQ matches docs/faq.md.')
} else {
  writeFileSync(readmePath, next)
  console.log('README.md’s FAQ updated from docs/faq.md.')
}
```

- [ ] **Step 1: Write the checker**

`packages/site/scripts/check-links.mjs`. This is the guard for the failure mode the whole base-path discipline exists to prevent.

```js
#!/usr/bin/env node
/**
 * Fail the build on an internal link that does not exist in `dist`.
 *
 * `astro dev` serves from the base path, so a hardcoded `/wiremock/` works locally and 404s in
 * production. Nothing catches that until someone clicks it on the live site. This walks the
 * built HTML and resolves every root-relative href and src against `dist`, which is exactly what
 * GitHub Pages will do.
 */
import { readdir, readFile, stat } from 'node:fs/promises'
import { existsSync } from 'node:fs'
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'

const here = dirname(fileURLToPath(import.meta.url))
const dist = join(here, '..', 'dist')
const BASE = '/mock-knight'

async function htmlFiles(directory) {
  const out = []
  for (const entry of await readdir(directory)) {
    const full = join(directory, entry)
    if ((await stat(full)).isDirectory()) out.push(...(await htmlFiles(full)))
    else if (entry.endsWith('.html')) out.push(full)
  }
  return out
}

const files = await htmlFiles(dist)
const failures = []

for (const file of files) {
  const html = await readFile(file, 'utf8')
  for (const match of html.matchAll(/(?:href|src)="(\/[^"#?]*)"/g)) {
    const url = match[1]
    if (!url.startsWith(`${BASE}/`)) {
      failures.push(`${file}: "${url}" does not start with ${BASE}/ — use href() from src/lib/href.ts`)
      continue
    }
    const relative = url.slice(BASE.length + 1)
    const candidates = [
      join(dist, relative),
      join(dist, relative, 'index.html'),
      join(dist, `${relative.replace(/\/$/, '')}.html`),
    ]
    if (!candidates.some((candidate) => existsSync(candidate))) {
      failures.push(`${file}: "${url}" resolves to nothing in dist`)
    }
  }
}

if (failures.length > 0) {
  console.error(`check-links: ${failures.length} broken internal link(s)\n`)
  for (const failure of failures) console.error(`  ${failure}`)
  process.exit(1)
}
console.log(`check-links: ${files.length} pages, every internal link resolves.`)
```

             | grep -qE '^(packages/site/|docs/images/|docs/faq\.md|design/|packages/web/src/styles/tokens\.css|schema/)'; then

        if: steps.touched.outputs.run == 'true'
